# Meridian GNU/Linux
A derivative of Arch Linux that comes ready to use with Paru, drivers, and practicality in a TUI setup program.
Based on the `archiso` bootable environment for live media, this distribution is intended for practicality and usage out of the box while being lightweight.

This distribution is currently not available and being developed in its alpha (or first unstable minor version) phase. Logos, features, and change logs are subject to change.

## Arch without the trouble
This distribution intends to be a bridge of vanilla Arch Linux's minimalism while providing practicality like other major Arch-based distributions without being controlling. It provides a good balance between being able to configure your system as the Arch philosophy strongly encourages while providing ease of use out of the box.

The distribution will also include `base-devel`, allowing users to begin developing and compiling programs immediately. Of course, configuration is always allowed and never limited, but practical for people who don't want to run every little step.

## Our philosophy
With Meridian Linux, our philosophy is providing practicality and minimalism. While other distributions may remake Arch Linux or be too similar to it, I want to strike a balance with this project as a new developer. Meridian Linux symbolizes navigating and discovering your system, while having its challenges and breathtaking aspects like a mountain peak or traveling an actual meridian.

## Releases and my story

Documentation may not be much as the project emerges, while contributions are majorly appreciated.

### AArch64 plan
Because Arch Linux has no official mainstream ARM64 distributions, I will consider these options AFTER the x86_64 release is stable:
1. Base it on Arch Linux ARM (ALARM) - A community-maintained port of Arch Linux for AArch64 and ARM32 based systems, most likely path
2. Base it on Asahi Linux - Great mainstream ARM64 support, but the only problem is making two architectures have different kernels, package managers and documentation. Very unlikely choice unless I have to.
